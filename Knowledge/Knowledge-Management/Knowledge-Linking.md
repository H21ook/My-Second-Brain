# Knowledge Linking

## Summary

Knowledge Linking is the practice of connecting related knowledge notes through meaningful relationships.

Individual notes contain knowledge.

Links create understanding between pieces of knowledge.

A connected knowledge network is more valuable than a collection of isolated notes because it shows how ideas relate to one another.

---

## Problem

Even well-written knowledge loses value when it exists in isolation.

Without links:

- related ideas remain hidden
- duplicate notes become more common
- navigation becomes difficult
- AI receives less context
- future learning becomes slower

A knowledge base should behave like a network, not only like a filing cabinet.

---

## When to Use

Create links whenever a meaningful relationship exists.

Examples include:

- prerequisite concepts
- broader or narrower concepts
- alternative approaches
- supporting ideas
- implementation examples
- project applications
- decision records
- related best practices

---

## When Not to Use

Do not create links simply because two notes mention the same word.

Avoid links that:

- add no useful context
- create visual clutter
- exist only for completeness
- force unrelated concepts together

Every link should help future understanding.

---

## Core Concepts

Knowledge Linking is based on relationships rather than hierarchy.

A note can have many meaningful connections.

Examples:

```text
Atomic Knowledge -> Knowledge Distillation
Knowledge Distillation -> Evergreen Knowledge
Prompt Engineering Principles -> AI Context Engineering
Retrieval-Augmented Generation -> Vector Embeddings
```

Each link answers a question such as:

- What should I understand first?
- What is closely related?
- What is an example?
- What is an alternative?
- Where is this applied?

---

## Types of Links

### Prerequisite

Knowledge that should be understood first.

Example:

```text
Knowledge Distillation -> Atomic Knowledge
```

### Related Concept

Concepts that naturally complement each other.

Example:

```text
Retrieval-Augmented Generation <-> Vector Embeddings
```

### Implementation

A practical application of a concept.

Example:

```text
Authentication Patterns -> JWT Authentication
```

### Project Application

A reusable concept connected to a specific project.

Example:

```text
AI Agent Architecture -> AI Sales Assistant Project
```

### Decision

A concept that influenced an important decision.

Example:

```text
Caching Strategies -> Use Redis for Caching
```

---

## How It Works

```text
Create Knowledge
  -> Identify Related Notes
  -> Add Meaningful Wikilinks
  -> Review Existing Links
  -> Improve Connections Over Time
```

The goal is not to maximize the number of links.

The goal is to maximize useful relationships.

---

## Best Practices

- Prefer a few strong links over many weak links.
- Link concepts, not keywords.
- Link reusable knowledge before project-specific notes.
- Review links whenever a note is significantly updated.
- Allow the knowledge graph to grow naturally.

---

## Common Mistakes

### Linking everything

A highly connected graph is not necessarily a useful graph.

Quality is more important than quantity.

### Using folders instead of links

Folders organize storage.

Links organize understanding.

Use both for different purposes.

### Duplicating information

Instead of copying explanations into multiple notes, link to the original concept.

### Ignoring relationships

Knowledge without relationships is difficult to discover and reuse.

---

## Trade-offs

Advantages:

- better navigation
- stronger knowledge graph
- reduced duplication
- improved AI context
- easier discovery
- more reusable knowledge

Disadvantages:

- requires ongoing maintenance
- poor-quality links create noise
- over-linking reduces clarity

---

## Examples

Poor:

```text
Prompt Engineering

No related notes.
```

Better:

```text
Prompt Engineering Principles

Related Notes:
- AI Context Engineering
- AI Agent Architecture
- Retrieval-Augmented Generation
- Knowledge Distillation
```

## Personal Insights

Links should capture meaning, not coincidence.

When I create a new note, I ask:

- What ideas made this note possible?
- What ideas become easier to understand after reading this?
- Which projects apply this concept?

If I cannot answer at least one of these questions, the note probably does not need additional links.

The strength of a Second Brain is not measured by the number of notes it contains, but by how effectively those notes work together as a connected system.
