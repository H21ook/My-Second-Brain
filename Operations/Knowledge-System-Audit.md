# Knowledge System Audit

## Purpose

This document defines the standard process for auditing and improving the AI Second Brain.

The objective is not simply to review documentation.

The objective is to preserve the consistency, maintainability, and long-term quality of the entire knowledge system.

Run this audit whenever:

- new documentation is created
- existing documentation is modified
- templates are added or changed
- standards are updated
- knowledge is reorganized
- a major project milestone is completed

---

# Audit Workflow

Follow these steps in order.

---

# Step 1 - Understand the System

Read and understand:

- [[00-Overview]]
- [[01-Knowledge-Philosophy]]
- [[02-Knowledge-Principles]]
- [[03-Knowledge-Lifecycle]]
- [[04-Note-Types]]
- [[05-Knowledge-Quality-Checklist]]
- [[06-AI-Working-Guide]]
- all templates relevant to the task

Do not begin making changes until the overall architecture is understood.

---

# Step 2 - Analyze the Change

Determine exactly what has changed.

Examples:

- new Knowledge Note
- new Template
- updated Principle
- new Standard
- folder reorganization
- workflow change

Clearly define the scope before continuing.

---

# Step 3 - Perform Impact Analysis

Determine whether the change affects:

## Foundation

- [[00-Overview]]
- [[01-Knowledge-Philosophy]]
- [[02-Knowledge-Principles]]
- [[03-Knowledge-Lifecycle]]
- [[04-Note-Types]]
- [[05-Knowledge-Quality-Checklist]]
- [[06-AI-Working-Guide]]

## Standards

- naming conventions
- metadata standards

## Templates

- existing templates
- new templates
- template consistency

## Knowledge

- related notes
- linked notes
- duplicate concepts
- project documentation

Nothing should be considered isolated.

Every permanent change may affect multiple documents.

---

# Step 4 - Identify Required Updates

Create a list of files that should be updated.

For each file include:

- file name
- reason
- proposed change
- priority

Example:

| File | Reason | Priority |
|---|---|---|
| [[00-Overview]] | New template introduced | High |
| [[06-AI-Working-Guide]] | Workflow updated | Medium |

---

# Step 5 - Ask for Approval

Never silently modify multiple documents.

Present the update proposal.

Wait for user approval before making structural changes.

---

# Step 6 - Apply Changes

After approval:

- update documentation
- improve links
- remove duplication
- maintain consistency
- update navigation where appropriate

Prefer improving existing documentation over creating new files.

---

# Step 7 - Validate the Knowledge System

Before finishing, verify:

## Architecture

- every document has one clear responsibility
- no duplicated responsibilities exist
- foundation remains simple

## Documentation

- terminology is consistent
- links are correct
- references are valid
- navigation remains clear

## Templates

- templates follow foundation rules
- templates do not redefine standards
- templates remain reusable

## Knowledge

- no unnecessary duplicates exist
- related knowledge is connected
- existing notes remain valid

---

# Final Report

Provide a report containing:

## Summary

Brief overview of the work completed.

## Files Updated

Explain why each file changed.

## Files Created

Explain why each file was necessary.

## Duplicates Removed

List merged or removed content.

## Remaining Recommendations

Suggest future improvements that would provide long-term value.

---

# Audit Principles

Always:

- think system-wide
- preserve consistency
- prefer improving over creating
- reduce duplication
- maintain simple architecture
- optimize for long-term maintainability

---

# Success Criteria

A successful audit leaves the knowledge system:

- more consistent
- easier to navigate
- better connected
- less duplicated
- easier for both humans and AI to understand

The purpose of an audit is not to produce more documentation.

The purpose is to improve the quality of the knowledge system.
