# Knowledge Note Template

## Purpose

This template defines the standard format for creating a permanent Knowledge Note.

Knowledge Notes represent long-term reusable knowledge.

Before creating a new note, ensure that the idea has passed the Knowledge Lifecycle and belongs to the **Knowledge** note type.

After writing, review the note using the Knowledge Quality Checklist.

---

# Instructions for AI

Before writing this note:

- Read [[00-Overview]] to understand the knowledge system.
    
- Follow [[02-Knowledge-Principles]] while writing.
    
- Ensure the note has completed [[03-Knowledge-Lifecycle]].
    
- Follow [[06-AI-Working-Guide]] when creating or changing permanent knowledge.
    
- Verify that a similar Knowledge Note does not already exist.
    
- Improve existing notes instead of creating duplicates whenever possible.
    

---

# Title

Use a concise and descriptive title.

The title should represent exactly one concept.

---

# Metadata

Use frontmatter when creating the actual note.

Example:

```yaml
---
title:
type: knowledge
status: draft
created:
updated:
tags:
  - knowledge
aliases:
related:
---
```

Follow [[08-Metadata-Standards]] when adding or changing metadata.

---

# Summary

Provide a short overview.

Answer:

- What is it?
    
- Why is it important?
    

Keep this section short enough that someone can understand the topic in less than one minute.

---

# Problem

Describe the problem this knowledge solves.

Explain why someone would need to understand this concept.

---

# When to Use

Describe situations where this knowledge is applicable.

Include:

- Common scenarios
    
- Prerequisites
    
- Expected outcomes
    

---

# When Not to Use

Explain situations where another approach is more appropriate.

Understanding limitations is as important as understanding usage.

---

# Core Concepts

List the essential concepts required to understand this topic.

Each concept should be short and focused.

---

# How It Works

Explain the internal process.

Prefer:

- Step-by-step explanations
    
- Bullet points
    
- Diagrams
    
- Simple workflows
    

Avoid unnecessary detail.

---

# Best Practices

Document recommendations that consistently produce good results.

Explain why each recommendation exists.

---

# Common Mistakes

List common misunderstandings and implementation mistakes.

Whenever possible, include how to avoid them.

---

# Trade-offs

Every solution has advantages and disadvantages.

Document both.

Avoid describing anything as universally "best."

---

# Examples

Provide practical examples whenever appropriate.

Examples may include:

- Code
    
- Commands
    
- Folder structures
    
- Prompt examples
    
- Diagrams
    
- Workflows
    

Examples should be realistic and reusable.

---

# Related Notes

Create links to related knowledge.

Possible relationships include:

- Prerequisites
    
- Alternatives
    
- Best Practices
    
- Troubleshooting
    
- Design Patterns
    
- Guides
    
- Project Notes
    

Knowledge should form a connected network.

---

# References

List useful external resources.

Prefer:

- Official documentation
    
- Specifications
    
- Books
    
- Research papers
    

Summarize external information instead of copying it.

---

# Personal Insights

Capture practical experience.

Examples:

- Lessons learned
    
- Production experience
    
- Better alternatives
    
- Things discovered through real-world usage
    

This section often becomes the most valuable part of the note.

---

# Review Checklist

Before completing this note, confirm:

-  One clear concept is covered.
    
-  The explanation is written in my own words.
    
-  The note is understandable without additional context.
    
-  Practical examples are included where useful.
    
-  Related notes are linked.
    
-  The note follows [[02-Knowledge-Principles]].
    
-  The note satisfies [[05-Knowledge-Quality-Checklist]].
    

---

# Continuous Improvement

Knowledge Notes are never considered finished.

Whenever better understanding becomes available:

- Improve explanations.
    
- Add better examples.
    
- Remove outdated information.
    
- Strengthen links to related notes.
    
- Simplify wherever possible.
    

The objective is continuous improvement rather than continuous creation.
