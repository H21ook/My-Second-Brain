# Knowledge Lifecycle

## Purpose

Knowledge is not created in a single step.

Every piece of knowledge moves through a lifecycle that transforms raw information into long-term reusable knowledge.

The goal is to continuously improve knowledge instead of simply collecting notes.

---

# Lifecycle Overview

```
Capture
    ↓
Evaluate
    ↓
Distill
    ↓
Organize
    ↓
Connect
    ↓
Apply
    ↓
Review
    ↓
Archive or Delete
```

---

# 1. Capture

Capture ideas as quickly as possible.

Sources may include:

- Conversations with AI
    
- Books
    
- Documentation
    
- Videos
    
- Research
    
- Personal experience
    
- Bugs and debugging
    
- Meetings
    
- Projects
    

At this stage:

- Don't worry about formatting.
    
- Don't worry about organization.
    
- Don't optimize.
    

The goal is simply to avoid losing valuable ideas.

Output:

- Inbox note
    
- Temporary note
    
- Daily note
    

---

# 2. Evaluate

Not everything deserves to become permanent knowledge.

Ask:

- Will this be useful again?
    
- Is this reusable?
    
- Does this improve future work?
    
- Is it better than existing knowledge?
    
- Is it only temporary?
    

If the answer is "No", discard it.

If "Yes", continue.

---

# 3. Distill

Transform information into knowledge.

Remove:

- unnecessary details
    
- duplicated information
    
- temporary context
    
- long conversations
    

Extract:

- concepts
    
- principles
    
- decisions
    
- best practices
    
- examples
    
- lessons learned
    

A distilled note should answer:

- What is it?
    
- Why is it useful?
    
- When should it be used?
    
- Trade-offs
    
- Common mistakes
    

---

# 4. Organize

Move the knowledge into its proper location.

Choose:

- correct category
    
- consistent naming
    
- appropriate tags
    
- metadata
    
- note type
    

Knowledge should always have a clear home.

---

# 5. Connect

Knowledge becomes more valuable when connected.

Create links to:

- related concepts
    
- prerequisites
    
- alternatives
    
- implementations
    
- projects
    
- references
    

The goal is to build a knowledge network instead of isolated notes.

---

# 6. Apply

Knowledge only becomes valuable when it is used.

Apply it in:

- software projects
    
- AI prompts
    
- architecture decisions
    
- documentation
    
- personal workflows
    
- business decisions
    

Whenever knowledge is used, improve it if new insights are discovered.

---

# 7. Review

Knowledge should evolve.

Review notes periodically to:

- improve explanations
    
- simplify content
    
- remove outdated information
    
- merge duplicates
    
- add better examples
    

Knowledge is never considered "finished."

For AI-assisted changes to permanent knowledge, follow [[06-AI-Working-Guide]] after review so impact analysis and update proposals are handled consistently.

For system-wide documentation maintenance, use [[Operations/Knowledge-System-Audit]] to validate affected files and cross-links.

---

# 8. Archive or Delete

Not every note deserves permanent storage.

Archive when:

- historically useful
    
- replaced by a newer version
    
- no longer actively used
    

Delete when:

- duplicated
    
- incorrect
    
- temporary
    
- no future value
    

Removing unnecessary knowledge keeps the Second Brain efficient.

---

# Lifecycle Rules

Every permanent knowledge note should have completed at least these stages:

- Evaluated
    
- Distilled
    
- Organized
    

Raw information should never become permanent knowledge.

Knowledge should continuously move through this lifecycle as understanding improves.

The objective is not to collect more notes.

The objective is to build better knowledge.
